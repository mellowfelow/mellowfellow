## CRITICAL

**C1 — Keyword-strategy doc is publicly downloadable.**
`/docs/keyword-cluster.txt` ships in the deploy root and is not blocked by `robots.txt`, `_headers`, or `_redirects`. Anyone can read the full keyword map — search volumes, KD, planned URLs, competitor gaps. WebForge Rule 12: strategy docs never ship to the public web.
Fix: remove `docs/` from the deploy (add an exclude / move out of web root), or at minimum `Disallow` + return 404. Also migrate it to the current `docs/PROJECT.md` + `docs/keyword-map.md` format.

**C2 — Store schema advertises payment methods the store does not accept.**
Homepage `OnlineStore` JSON-LD: `"paymentAccepted": "Cash, Credit Card, Bitcoin, USDT, Apple Pay, PayPal"` and `"currenciesAccepted": "USD, BTC, USDT"`. Every other surface (checkout UI, `llms.txt`, `auth.md`, all `.well-known/*`, MCP server-card) says **crypto (BTC/USDT) + bank transfer only** — and the card option was removed in commit `6c1564f`. This is a capability inaccuracy (WebForge Rule 10) and a Merchant-listing risk.
Fix: `"paymentAccepted": "Bitcoin, USDT, Bank Transfer"`.

**C3 — No custom 404 page.**
No `404.html` at root. Cloudflare Pages serves a bare default; bad-URL hits get no nav, no recovery path, and Search Console logs soft-404 confusion.
Fix: add a branded `404.html` (nav + search + top categories), `noindex`.

## WARNINGS

**W1 — Heading order is broken site-wide.** The Shop mega-menu renders 7 `<h4>` category headings (`Disposable Vapes`, `Vape Cartridges`, …) before the page `<h1>` on all 342 pages. Screen-reader heading navigation and SEO outline both start with orphaned H4s.
Fix: change the mega-menu `<h4>` to `<p class="mega-col-title">` (or `<span>`), style unchanged.

**W2 — No skip-link / no `<main id>` target.** No "Skip to content" link anywhere; `<main>` has no stable `id` (`id="page-home"` on home, none elsewhere). WCAG 2.4.1 (A).
Fix: add `<a class="skip-link" href="#main">Skip to content</a>` as first body child; set `<main id="main">` on every page.

**W3 — No `prefers-reduced-motion` handling.** The announcement bar auto-scrolls (`.ann-track`) and there are hover/scroll transitions; zero `@media (prefers-reduced-motion: reduce)` blocks in any CSS. WCAG 2.3.3 + WebForge design-quality gate.
Fix: add a reduced-motion block that pauses `.ann-track` animation and neutralises transitions/transforms.

**W4 — Duplicate / cannibalising product pair.** `/product/microdose-m-fusions-delta-9-thc-cbd-80mg-watermelon/` and `/product/microdose-m-fusions-gummies-delta-9-thc-cbd-8ct-80mg-watermelon/` have identical `<title>` ("Microdose Delta 9 THC + CBD 80mg Watermelon | Mellow Fellow"), both self-canonical, both indexable, both in the sitemap.
Fix: if same product → 301 one to the other (or canonical the weaker to the stronger + drop from sitemap). If genuinely different SKUs → differentiate title/H1/description.
(Note: the `…-2` / `…-3` suffixed product dupes ARE handled correctly — `noindex` + canonical to primary + excluded from sitemap.)

**W5 — Thin content on Contact and Wholesale.** Contact = 107 words, Wholesale = 95 words, neither has a form. Contact shows the email as plain text (not even a `mailto:`); Wholesale has no WhatsApp/email link in the body at all. Weak for "mellow fellow wholesale" / "contact" intent and no lead capture.
Fix: add a real contact form + a wholesale enquiry form (Web3Forms, same CORS method as checkout) with `/thank-you-contact/` and `/thank-you-wholesale/` pages; expand body copy to 250–400 words each.

**W6 — `sameAs` missing from Organization/Store schema.** No social/external profile URLs anywhere in schema. Weakens entity consolidation for Google and AI engines.
Fix: add a `sameAs: [...]` array with the brand's real Instagram / X / Reddit / LinkedIn / Trustpilot / official-brand URLs (only real ones).

**W7 — Sitemap `<lastmod>` is stale and inconsistent.** `sitemap.xml` index says `2026-07-31`; `sitemap-products.xml` entries say `2026-06-07`; pages carry `og:updated_time` `2026-08-04`; checkout code changed in August/September. Conflicting freshness signals.
Fix: regenerate all sitemaps with a real current `<lastmod>` and keep the index + children in sync.

**W8 — `paymentAccepted` aside, homepage Store schema has smaller gaps.** `logo.url` points to `/images/cat-disposables.webp` (a category photo, not the logo — `mf-logo-new.webp` exists); `founder[]` Person entries have no `name`; no `numberOfItems`. `image` refers to `hero-shop.webp` which has no AVIF sibling.
Fix: point `logo` at the real logo; either name the founders or drop the `founder[]` array; add `numberOfItems`.

**W9 — 339 pages carry a legacy `<meta name="keywords">` tag.** Ignored by Google/Bing; on blog posts it's tokenised garbage (`content="mellow fellow, what, is, thcp, and, does…"`). Pure noise, hands keyword targeting to competitors.
Fix: remove the meta keywords tag from the template.

**W10 — Meta-description length outliers.** 10 pages > 160 chars (max 176 — 4 blog, 6 product), 4 pages < 110 chars (3 vape-cart-duo products at 92–107). 
Fix: trim/expand to the 120–158 band.

**W11 — `priceValidUntil` is `2026-12-31` on every product.** ~3.5 months out. Google Merchant listings start warning as this approaches, then drop the price rich result when it passes.
Fix: roll to `2027-12-31` (and add a note to bump it annually, or generate it as today + 12 months).

**W12 — Render-blocking CSS + heavy shared JS.**
- 3 separate render-blocking stylesheets in `<head>` (`style-v12.css` 63KB + `site-v13.css` 33KB + `fonts.css` 7KB), unminified.
- `products-lookup.js` (153KB) loads on **every** page including blog/legal pages that never search products.
Fix: minify + concatenate the CSS to one file; inline critical CSS; load `products-lookup.js` only where search/cart lives (or split the lookup table and defer). Confirm impact in the live Lighthouse pass.

**W13 — `og:image` quality.** Homepage `og:image` = `hero-slide-1.webp` at 1920×700 (not the 1.91:1 / 1200×630 social ratio). Blog posts use generic category images (`cat-thcp.webp`) as `og:image` even though post-specific art exists (`blog-*.webp`).
Fix: generate 1200×630 OG images; map each blog post to its own `blog-*` image.

**W14 — Font-face src filenames scrambled.** In `fonts.css`, `Cormorant Garamond` italic **weight 400** points at `cormorant-garamond-italic-300.woff2`; the 300/400 latin vs latin-ext files are crossed. Wrong weight renders in places.
Fix: correct each `@font-face` `src` to its matching file.

**W15 — Emails in plaintext inside JSON-LD.** Homepage + About page emit `"email": "info@mellowfellowcarts.com"` unencoded in JSON-LD (WebForge wants entity-encoded everywhere). Low harm, easy fix.

**W16 — `SearchAction` target.** `WebSite` schema points search at `/shop?q={search_term_string}`, but on-site search is a JS overlay — confirm `/shop?q=` actually filters server-agnostically (deep link works) or change the target to the real search behaviour.

## NEW / UPGRADED FINDINGS FROM LIVE DATA

**D1 (CRITICAL) — Internal links don't use trailing slashes; canonicals do. 311 pages sit in "Page with redirect" and the count is climbing.**
Every canonical is `…/path/` (trailing slash). But **145 of 153 internal links on the homepage** (and ~all nav / mega-menu / footer / breadcrumb / related-product links site-wide) point at `…/path` with **no** slash. Cloudflare Pages redirects non-slash → slash, so Googlebot crawls a redirect on nearly every internal link, files the non-slash URL under "Page with redirect", and link equity passes through a 301 hop instead of landing directly. Semrush shows the slash and non-slash forms of the same blog post both ranking.
Fix: normalise **every** internal `href` to include the trailing slash (nav, mega-menu, mobile drawer, footer, breadcrumbs, product cards, related products, in-content links, `ItemList`/`BreadcrumbList`/`Offer` `url` fields, `llms.txt`, agent files). One template pass. Then re-submit sitemap + request re-crawl.

**D2 (WARNING) — Bing only discovered 10 of 327 sitemap URLs.**
Bing reads `sitemap.xml` (the index) and reports 10 URLs — it isn't expanding `sitemap-products.xml` / `-categories.xml` / `-blog.xml`. 
Fix: submit the four child sitemaps to Bing individually (`sitemap-pages.xml`, `sitemap-categories.xml`, `sitemap-products.xml`, `sitemap-blog.xml`), and confirm each child `<loc>` in the index is itself reachable and valid.

**D3 (WARNING) — IndexNow is not actually live.**
Bing flags it as a high-severity gap. The key file exists in the repo but nothing pings `api.indexnow.org` on publish, and Bing hasn't verified the key.
Fix: verify the key in Bing WMT (IndexNow section), and add an IndexNow ping to the deploy step (POST changed URLs to `https://api.indexnow.org/indexnow?url=…&key=…`).

**D4 (WARNING, was C2) — payment schema mismatch is also live in "Merchant listings" (866 valid).** With 866 merchant listings live in GSC, the incorrect `paymentAccepted` (Credit Card / PayPal / Apple Pay / Cash) is being served at scale. Same fix as C2 — corrected to crypto + bank transfer.

**D5 (STRATEGIC) — the site is one blog post deep.**
~90% of Google traffic and ~80% of Semrush traffic come from a single post. Homepage (pos 21), categories (pos 20+) and products barely rank; `mellow fellow carts` — the literal domain phrase — is pos 14.9 at 1.6% CTR, and `themellowfellow.shop` outranks with 3× traffic. Combined with AS 7 and a toxic link profile, the growth blockers are **off-page authority** and **weak commercial-page optimisation**, not the (strong) technical/on-page base.
Fix track (post-cleanup): disavow toxic links; earn a handful of real cannabis/industry links + directory + Trustpilot/Reddit presence; rework homepage + top category pages to actually target `mellow fellow carts`, `mellow fellow vape`, `mellow fellow gummies`, `mellow fellow flower`; add the missing `sameAs`.
